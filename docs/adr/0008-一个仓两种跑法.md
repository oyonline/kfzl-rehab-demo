# ADR 0008 · 一个仓两种跑法，不分仓

- 日期：2026-08-29
- 状态：生效
- 相关代码：`server/index.ts` 的 `AI_ENABLED`

## 背景

项目有两个载体：**本地版**（参赛人电脑，终端启动，断网可演，比赛主力）
与**扣子线上版**（备份与对外链接，接平台大模型）。
两者在 AI 能力、素材可得性上存在差异。

## 备选

1. **分两个仓**：各自演进，互不干扰。
2. **一个仓两个分支**：长期并行，需要频繁 cherry-pick。
3. **一个仓，差异用运行时开关**。

## 裁决

**方案 3。** 差异收敛到环境变量：容器内存在 `COZE_WORKLOAD_IDENTITY_API_KEY`
时启用真实模型，本地没有则自动关闭。

## 后果

- 避免了两份代码分头漂移 —— 这是分仓最常见的失败方式。
- 代价：所有环境差异必须显式建模为开关，隐式依赖会在另一个环境炸掉。
  实际发生过：只读沙箱不允许模块加载阶段写盘、`data/` 目录 gitignore 写法差异。
- **注意**：本条针对的是「本地版 vs 扣子线上版」这一对差异。
  比赛线与产品线的隔离是另一回事，见 [0009](0009-比赛线与产品线用-tag-隔离.md)。
