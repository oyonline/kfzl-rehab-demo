# ADR 0014 · 医疗内容审核走页面 + 审计日志，不改代码

- 日期：2026-08-30（P6）
- 状态：生效
- 相关代码：`src/pages/therapist/ReviewView.tsx`、`server/routes/review.ts`、`0003_review_audit.sql`

## 背景

项目起草了三类医疗性内容：咨询预设答案（`qa.ts`）、饮食与健康指导（`guidance.ts`）、
训练分步说明（`videoSteps.ts`）。这些**必须由康复专业人员审核**才能用于正式演示。

原做法是在文件头部写 `REVIEW REQUIRED` 标记，审核后由开发改代码。

## 备选

1. **维持文件标记**：审核动作必须经过开发，专业人员无法自助。
2. **做成配置文件**：仍需要有人改文件并重新部署。
3. **做成后台页面**，审核状态入库。

## 裁决

**方案 3。** 康复师端顶栏「内容审核」（`/therapist/review`），
四类内容分页签逐条通过或驳回。

## 后果

- **驳回的内容立即停止对家属展示**：语料退出检索、文案不再下发。
  这是关键 —— 审核不再是"贴个标记"，而是有真实执行效果的开关。
- 每次批准与驳回都写**审计日志**（含操作人与时间），可在同页翻阅。
  医疗内容的审核必须留痕，这是合规要求而非产品功能。
- 三个源文件仍是内容的**初始来源**（由种子灌进库），
  但审核状态只存在数据库里 —— **改文件头部的 REVIEW 标记不再是审核动作**。
- 知识库语料不由种子管理（归 `pnpm kb:import`），因此审核列表的条数取决于导入了什么。
