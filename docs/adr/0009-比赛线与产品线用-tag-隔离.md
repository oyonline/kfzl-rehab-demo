# ADR 0009 · 比赛线冻结为 tag，产品线在 main 演进

- 日期：2026-08-30
- 状态：生效
- 相关标记：tag `demo-competition-20260830`

## 背景

比赛 9/10 封版。同期用户裁决把项目推向**真实产品**：多患者、多康复师、
真实鉴权、持久层、知识库检索。这些改动足以动摇比赛版的稳定性。

关键冲突：比赛版排期成立的前提写得很明确 —— **不做后端、不做知识库、
不做姿势识别、不做真视频上传**。任何一项加回来，排期即失效。而产品线要加回两项。

## 备选

1. **推迟产品化到比赛之后**：安全，但白白浪费两周。
2. **在分支上做产品线，比赛后合并**：合并成本随时间指数上升。
3. **给比赛版打 tag 冻结，main 转产品线**。

## 裁决

**方案 3。** tag `demo-competition-20260830` 是比赛线的不可变基线。

## 后果

- 比赛线基线**不受 main 后续演进影响**，排期前提继续成立。
- 比赛若需 hotfix，**从该 tag 拉分支，不得用 main** —— main 已是另一套架构。
- 「不做后端、不做知识库」这条排期前提**只约束比赛线**，产品线不适用。
  两条线不共享排期。
- 代价：任何文档都必须先声明"你在哪条线上"，否则读者会拿错架构去理解代码。
  本仓 README 与 AGENTS.md 开头都因此加了分线说明。
