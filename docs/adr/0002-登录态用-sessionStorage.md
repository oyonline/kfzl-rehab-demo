# ADR 0002 · 登录态用 sessionStorage，不用 localStorage / Cookie

- 日期：2026-08-27 确立；2026-08-30 后端化后重新确认
- 状态：生效
- 相关代码：`src/auth/auth.ts`

## 背景

双端要**并排同时在线**演示：左窗家属端、右窗康复师端。
两个窗口是同源的两个标签页。

## 备选

1. **localStorage 存登录态**：同源共享 —— 两个标签页看到同一份登录态。
2. **Cookie 存登录态**：同源共享，且自动随请求发送，实现最省事。
3. **sessionStorage 存登录态**：按标签页隔离。

## 裁决

**sessionStorage**。演示数据可以同源共享，登录态绝对不行。

## 后果

- 前 1、2 两个方案都会让两端**互相顶掉会话**：家属端登录后，康复师端标签页的会话被覆盖，
  两个角色无法同时在线，**并排演示当场失效**。这是实测踩过的坑，不是推演。
- 2026-08-30 鉴权搬到服务端后，令牌改为 JWT，但存储位置不变 ——
  仍是 sessionStorage，经 `Authorization: Bearer` 头回传，**不得改用 Cookie**。
- 代价：令牌不能自动随请求发送，每个请求要手动带头；
  且 `EventSource` 不能带自定义头，直接导致了 [0011](0011-实时推送不用-EventSource.md)。
- 刷新标签页会丢登录态。演示场景可接受。
