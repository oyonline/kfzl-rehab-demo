# ADR 0001 · 做双端而非只做家属端

- 日期：2026-08-27（推翻 2026-08-23 的「只展示家属视角」）
- 状态：生效

## 背景

初版方案只做家属端。演示时暴露出一个问题：家属端单独看，
就是一个打卡小程序 —— 评委和甲方都会问"这和市面上的打卡应用差在哪"。

## 备选

1. **只做家属端**：工作量小，但价值主张说不清楚。
2. **做双端**：家属端 + 康复师端，工作量约翻倍。
3. **家属端 + 康复师端切图**：康复师端不做交互，只放静态图。演示时无法证明数据真的联通。

## 裁决

**做双端**，并把演示主线定为一条闭环：

> 家属端执行并打卡 → 康复师端远程看到 → 康复师回写指导 → 家属端收到

## 后果

- 价值主张变成可演示的事实：康复师不必上门，在工作台就能看到执行情况并给出指导。
- 工作量翻倍，且引出后续一连串约束：两端要同源（[0003](0003-两端同源部署.md)）、
  登录态要隔离（[0002](0002-登录态用-sessionStorage.md)）、数据要跨端同步（[0011](0011-实时推送不用-EventSource.md)）。
- 演示必须开两个窗口并排，对现场屏幕分辨率提出要求。
