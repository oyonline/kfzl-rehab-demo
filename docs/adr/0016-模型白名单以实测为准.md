# ADR 0016 · 模型白名单以实测为准，不信平台文档

- 日期：2026-08-31
- 状态：生效
- 相关代码：`server/index.ts` 的 `LLM_MODELS` / `DEFAULT_LLM_MODEL`、
  `src/pages/patient/ChatView.tsx` 的 `LLM_OPTIONS`、`probe-models.ts`

## 背景

2026-08-30 发现 AI 咨询整体故障。根因：默认模型 `doubao-seed-1-8-251228`
**被平台下线**。代码没错，是脚下的平台变了。

## 备选

1. **换一个平台文档里列出的新模型**：最快。
2. **写探测脚本逐个实测，用实测通过的建白名单**。
3. **每次调用前先探活**：可靠但每次对话多一次往返。

## 裁决

**方案 2。** `probe-models.ts` 逐个探测候选模型，实测通过的进白名单。

## 后果

- **平台文档不可信**：实测发现文档列出的 `glm-5` / `minimax-m2.x` / `qwen-3.5`
  均返回 not found。**以探测为准**，这是本条 ADR 的核心结论。
- 白名单落地 4 个模型，默认 `doubao-seed-2-0-lite-260215`；
  前端提供模型选择器，选项与服务端白名单**一一对应，改动须两侧同步**。
- **前端传来的 `model` 字段不被信任**：不在白名单的一律回退默认值并告警。
  前端只传友好选项，但这不构成信任理由。
- **故障期间系统表现为优雅降级而非崩溃**，验证了 [0015](0015-本地立刻关闭-AI.md)
  那套链路：模型返回空 → 前端 `if (!fullText.trim()) throw` 判失败 →
  降级预设答案。且降级时**「依据」仍然真实** —— 检索不依赖模型（[0007](0007-展示依据而非思考链.md)）。
- **运维约定**：演示前跑一遍 `probe-models.ts` 确认模型仍在线。
  平台快照会再次停运，这不是一次性问题。
