# 架构决策记录（ADR）

本目录记录项目过程中做出的**关键技术与产品决策**：为什么这么做、当时有哪些备选、
选定后付出了什么代价。

> **为什么要有这个目录**
>
> 代码能说明"做成了什么"，说明不了"为什么不是另一种做法"。
> 很多看起来奇怪的实现（比如不用 `EventSource`、比如把 313MB 视频放进 git）
> 都是权衡的结果 —— 没有记录的话，后来者会当成疏忽而"顺手修好"，
> 然后踩回同一个坑。

## 格式

每条包含四段：**背景**（当时的处境）、**备选**（考虑过什么）、**裁决**（选了什么）、
**后果**（付出的代价与产生的约束）。被推翻的决策**不删除**，标注为「已推翻」并指向新决策 ——
推翻本身也是决策记录的一部分。
