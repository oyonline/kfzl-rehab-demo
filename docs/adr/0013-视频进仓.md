# ADR 0013 · 17 个训练视频进 git 仓库

- 日期：2026-08-30（**推翻 2026-08-29 的「视频不进 git、随压缩包另发」**）
- 状态：生效
- 相关路径：`public/videos/`（17 个 `.mp4`，约 313 MB）

## 背景

甲方交付 21 个视频，选用 17 个。视频总量约 313 MB，
放进 git 会让仓库体积膨胀且不可逆。

## 备选

1. **不进 git，随 U 盘 / 网盘压缩包另发**（08-29 的原裁决）。
2. **放外部对象存储 / CDN**，代码里引用 URL。
3. **进 git 仓库**。
4. **Git LFS**。

## 裁决

**方案 3，进仓。** 推翻 08-29 的原裁决。

## 后果

**为什么推翻方案 1**：扣子线上版从 GitHub 拉代码构建，`.gitignore` 排除视频
等于线上永远拿不到素材 —— 全部 `/videos/*.mp4` 返回 404。
实测确认过：曾有人把 1 个视频提交到 `assets/`，但目录不进构建产物、
文件名与 `videos.src` 对不上，属无效尝试。

**为什么排除方案 2**：违反 [0004](0004-不引入外部依赖.md) ——
现场演示要求断网可用，不能用外部对象存储或 CDN 当视频源。

**压缩不可行（实测）**：转码只省约 20%，且有 5 条转码后**反而变大**。

**代价（不可逆）**：`.git` 约 347 MB。clone 变慢，需在部署文档里预留时间。
Git LFS 未采用 —— 引入额外工具链，参赛人电脑上多一个安装步骤与故障点。

**兜底仍然保留**：文件缺失时 `VideoStage` 的 `onError` 退回分步图文，不黑屏。
