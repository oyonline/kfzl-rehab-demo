# ADR 0012 · 写操作保持同步签名，内部乐观更新

- 日期：2026-08-30
- 状态：生效
- 相关代码：`src/store/store.ts`

## 背景

数据搬到服务端前，打卡是浏览器内存级操作 —— 点一下立刻变。
搬到服务端后，每次打卡要过一次网络。

## 备选

1. **改成异步函数，等服务端返回再更新界面**：最诚实，但打卡会卡顿，
   且 16 个消费方全部要改成 `await`。
2. **保持同步签名，内部乐观更新**：先改本地缓存立刻重渲染，再把请求发出去。
3. **同步签名 + 完全忽略失败**：最快，但会留下假的成功状态。

## 裁决

**方案 2。** 且**失败时必须回退**：提交失败则从服务端重新拉取，
界面退回真实状态（对勾自己消失），**而不是留着一个假的成功**。

## 后果

- 打卡仍是点一下就变 —— 演示主线不因为换了存储而变慢。
- 14 个对外函数签名一个没改，16 个消费方零改动。
- 代价：界面可能短暂显示一个随后被撤销的状态。这是有意的取舍 ——
  在演示场景里，"偶尔闪回"优于"每次都卡"。
- 方案 3 被明确排除：留着假的成功，等于在医疗场景里谎报"已完成训练"。
