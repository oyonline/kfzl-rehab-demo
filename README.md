# 居家康复智能助手（双端演示原型）

面向脑卒中居家康复场景的 PC 双端可交互原型。演示主线是一条闭环：

> 老人/家属端执行并打卡 → 康复师端远程看到 → 康复师回写指导 → 家属端收到

这条链路回答的是"区别于普通打卡小程序的价值在哪"：康复师不必上门，在工作台就能看到执行情况并给出指导。

## 运行

```bash
npm install
npm run dev
```

| 入口 | 本地地址 | 账号 | 密码 |
|---|---|---|---|
| 老人 / 家属端 | `http://localhost:5173/patient` | `limin` | `123456` |
| 康复师端 | `http://localhost:5173/therapist` | `wangxiulan` | `123456` |

登录仅账号密码，无验证码、无扫码、无第三方授权。表单已预填，现场无需手动输入。

**账号与另一端入口链接刻意不显示在登录页上** —— 那是排练资料，不是产品的一部分，上屏会削弱真实感。需要时查本文件。

**建议开左右两个窗口并排演示**：左边家属端打卡，右边康复师端会自动刷新，无需手动切换。

## 三条硬约束

**1. 两端必须同源部署。**
必须是同一域名下的两个路径（如 `example.com/patient` 与 `example.com/therapist`）。跨域名则 localStorage 不互通，联动闭环直接断裂，只能退回切图演示。

**2. 登录态必须用 sessionStorage，不得改回 localStorage。**
演示数据走 localStorage（同源共享，这是联动的基础）；登录态走 sessionStorage（按标签页隔离）。若登录态放进 localStorage，两端会互相顶掉会话，家属与康复师无法同时在线，并排演示当场不成立。

**3. 不引入任何外部字体、图标库或 CDN。**
图标为内联 SVG，字体用系统字体。现场网络不可控，断网也必须完整呈现。

## 结构

```
src/data/types.ts    双端共用数据契约（已冻结，改动须两端同步）
src/data/seed.ts     虚构案例、任务计划、视频清单、打卡历史
src/store/store.ts   localStorage + 跨标签页订阅
src/auth/auth.ts     账号密码登录（sessionStorage）
src/styles/          设计令牌与组件样式
src/pages/patient/   老人 / 家属端
src/pages/therapist/ 康复师端
```

打卡历史用固定模式生成而非随机数，保证每次演示看到的日历完全一致，可反复排练。

## 内容边界

案例人物与数据均为虚构，不对应任何真实个人。

- 不编造用药剂量与评估量表分值 —— 页面一律不展示具体数值，待康复专业人员提供后填入；
- 不得出现"已由医生确认""已真实接入""已同步医院系统"等冒充生产事实的措辞；
- 真实病历原件与直接身份信息不得进入本仓。
